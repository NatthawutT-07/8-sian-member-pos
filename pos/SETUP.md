# POS รุ่นเริ่มต้น

## โครงสร้าง

- `pos/web`: หน้าคิดเงิน แยกจากเว็บสมาชิกใน `frontend`
- `pos/desktop`: Electron สำหรับ Windows เปิดหน้า `/pos/` ของ backend
- `backend/src/pos`: API ของ POS ใช้ PostgreSQL เดิม แต่ตาราง `PosProduct` และ `PosSale` แยกจากสมาชิก
- `backend/prisma/migrations/202610290001_pos`: migration ที่ต้อง deploy ก่อนเริ่มใช้งาน
- `backend/prisma/migrations/202610290002_pos_users_shifts`: บัญชีพนักงาน USER เซสชัน POS และรอบเปิด–ปิดร้าน
- `backend/prisma/migrations/202610290004_pos_groups_coupons`: กลุ่มสินค้า กติกาส่วนลดคูปอง การจองสิทธิ์ และยอดส่วนลดบนบิล
- `backend/prisma/migrations/202610290005_campaign_signed_price`: ให้ฐานข้อมูลรับ extraPrice ติดลบตามความหมายส่วนลดของ API และเว็บสมาชิกเดิม

## เริ่มใช้งาน

1. จาก root รัน `npm.cmd run generate -w backend` และ `npm.cmd run migrate -w backend` กับฐานข้อมูลเป้าหมาย (สำรองข้อมูลก่อน deploy production)
2. ตั้ง `POS_ORIGIN` ใน backend ให้ตรง origin ที่ให้บริการ `/pos/` เช่น `https://api.example.com` (ไม่มี path และไม่มี slash ท้าย)
3. รัน `npm.cmd run dev:api` แล้วเปิด `http://localhost:3001/pos/`
4. เข้าสู่เว็บแอดมิน แล้วเลือกแท็บ **พนักงานและสินค้า POS** สร้างชื่อผู้ใช้ ชื่อพนักงาน และรหัสผ่าน (อย่างน้อย 8 ตัว) ระบบกำหนด role `USER` ให้เอง เพิ่มสินค้าจริง ราคาเป็นบาท และรหัสบาร์โค้ด/QR สินค้าที่แท็บนี้ พนักงานไม่มีสิทธิ์เปลี่ยนสินค้า/ราคาใน POS
5. ตั้งเครื่องสแกนเป็น USB/Bluetooth HID keyboard พร้อม Enter suffix แล้ววางโฟกัสในช่องสแกน เครื่องอ่าน QR ต้องเป็นรุ่น 2D
6. ช่อง **เบอร์สมาชิก / QR สมาชิก / บาร์โค้ดสินค้า** อยู่ใต้รายการสินค้าด้านล่างจอ รับเบอร์สมาชิก 10 หลัก (ใส่ขีดหรือเว้นวรรคได้) หรือ QR สะสมครั้ง `8SM-...` จากหน้าสมาชิก กด Enter หรือ **เพิ่ม / ค้นหา** แล้วตรวจชื่อและกด **ยืนยันใช้สมาชิกกับบิลนี้** ระบบผูกสมาชิกกับบิลและสะสมหนึ่งครั้งเมื่อบันทึกชำระสำเร็จเท่านั้น รหัสสินค้าใช้เพิ่มรายการ ถ้ารหัสตรงสินค้าที่เปิดขายอยู่จะให้ความสำคัญกับสินค้าก่อนค้นเบอร์

## กลุ่มสินค้าและส่วนลด

หน้า POS ใช้ปุ่มกลุ่ม **หลัก / ส่วนลด / โปรโมชั่น** แทนช่องค้นหาชื่อสินค้า เลือกรายการในกลุ่มเพื่อเพิ่มเข้าบิล ตั้งกลุ่มและราคาผ่านเว็บแอดมินแท็บ **พนักงานและสินค้า POS** สินค้าเดิมอยู่กลุ่มหลักโดยอัตโนมัติ กลุ่มโปรโมชั่นเป็นสินค้าที่กำหนดราคาไว้ตามปกติ ส่วนกลุ่มส่วนลดให้แอดมินกรอกจำนวนบาทที่จะลด ระบบบันทึกเป็นราคาติดลบ เลือกได้รายการละหนึ่งครั้ง และไม่ให้ส่วนลดเกินยอดสินค้า

## คูปองส่วนลดเป็นบาท

1. POS ใช้ `Campaign.extraPrice` ของแคมเปญที่คูปองสมาชิกใบนั้นอ้างอิงโดยตรง เป็นจำนวนบาทตามระบบเดิม: `-20` ลด 20 บาท, `0` ไม่มีส่วนลดเป็นบาท, `79` เป็นค่าเพิ่ม 79 บาทและไม่นำมาหักเป็นส่วนลด ตั้งมูลค่าที่แท็บ **แคมเปญคูปอง** ได้ทันที ไม่ต้องตั้งมูลค่าส่วนลด POS ซ้ำ ส่วนยอดขั้นต่ำตั้งได้ที่ **พนักงานและสินค้า POS → ส่วนลดคูปองสมาชิกสำหรับ POS** ค่าเริ่มต้นขั้นต่ำคือ 0
2. เปิดร้าน เพิ่มสินค้า จากนั้นพิมพ์รหัสคูปอง **32 หลัก** จากหน้าสมาชิก หรือยิงเครื่องสแกนลงช่อง **คูปองส่วนลด** แล้วกด Enter หากยิงในช่องสมาชิก ระบบจะส่งไปตรวจคูปองให้เช่นกัน เครื่องยิงใช้โหมด HID keyboard + Enter suffix
3. Backend ตรวจเจ้าของ คูปองยังไม่ใช้ อายุคูปอง อายุบาร์โค้ด แคมเปญ/ลำดับสิทธิ์ ยอดขั้นต่ำ และจำนวนส่วนลด จองคูปองให้บิล/พนักงานนี้ 5 นาที (หรือจนรหัสหมดอายุ ถ้าถึงก่อน) สมาชิกของคูปองจะปรากฏที่บิลโดยอัตโนมัติ ถ้าผูกสมาชิกไว้แล้วต้องเป็นคนเดียวกัน
4. ใช้ได้หนึ่งคูปองต่อบิล และใช้ร่วมกับรายการ **กลุ่มส่วนลด** ไม่ได้ จำนวนลดไม่เกินยอดบิล สแกนอย่างเดียวไม่ตั้ง usedAt และไม่สะสมครั้ง
5. เมื่อปิดบิล Backend ตรวจซ้ำและบันทึกยอดก่อนลด ส่วนลด ยอดสุทธิ การใช้คูปอง การยกเลิกบาร์โค้ด สะสมครั้ง และ audit ใน transaction เดียว Retry ใช้เลขบิลและยอดเดิม ใบเสร็จแสดงชื่อคูปองและส่วนลด รายงานรายวัน/ปิดร้านนับยอดสุทธิหลังลด
6. กด **นำคูปองออก** หรือ **ล้างบิล** เพื่อคืนการจอง โดยคูปองยังไม่ถูกใช้ ถ้าปิดแอปหรือเน็ตหลุดก่อนจ่าย การจองจะหมดอายุเอง ถ้าเครือข่ายหลุดหลังส่งชำระ ให้ตรวจผลบิลเดิมก่อนรับเงินใหม่

รหัสคูปองดิบไม่ถูกเก็บใน localStorage, URL หรือ audit; ฝั่งเครื่องเก็บเพียง reservationId และข้อมูลที่ใช้แสดงบิล การเปิดบาร์โค้ดใหม่ในหน้าสมาชิกทำให้ reservation ที่อ้างรหัสเก่าใช้ชำระไม่ได้ ต้องสแกนใหม่ การเปลี่ยน extraPrice ระหว่างคิดเงินต้องสแกนเพื่อตรวจยอดใหม่ก่อนชำระ มูลค่าที่บันทึกบนบิลสำเร็จแล้วไม่เปลี่ยนตามแคมเปญภายหลัง คอลัมน์เก่า posDiscountSatang คงไว้สำหรับข้อมูลเดิม แต่ไม่ถูกอ่านหรือแก้ผ่าน POS อีกแล้ว ยังไม่มีโค้ดโปรโมชั่นแบบข้อความที่ใช้ร่วมกันหลายคน เช่น SAVE20 หรือส่วนลดเปอร์เซ็นต์

## บัญชีและสิทธิ์

POS รับเฉพาะบัญชี `PosUser` ที่ active และ role `USER` เท่านั้น ไม่อ่านบัญชี `Admin` และไม่รับ `AdminSession` บัญชีแอดมินเดิมจึงเข้า POS ไม่ได้ บัญชี USER เข้า API แอดมินไม่ได้ ไม่มีรหัสเริ่มต้น ให้ร้านสร้างบัญชีผ่านเว็บแอดมิน แล้วใช้บัญชีพนักงานเข้า `/pos/` หรือโปรแกรม Windows การระงับบัญชีบนเว็บยกเลิกเซสชันพนักงานทันที

## เปิดร้าน ปิดร้าน และรายรับรายวัน

รุ่น 0.3.0: เมื่อยืนยันปิดกะแล้ว ระบบแสดง **ใบสรุปรายได้ปิดกะ** และโปรแกรม Windows จะส่งพิมพ์ให้เครื่องที่เลือกไว้ ใบสรุปมีเวลา/ผู้เปิด–ปิดกะ จำนวนบิล ยอดเงินสดและเงินโอนแยกกัน รายการสินค้าพร้อมจำนวนและยอด ส่วนลดคูปอง ยอดสุทธิ และการตรวจนับเงินสด (เงินตั้งต้น/ควรมี/นับจริง/ขาด–เกิน) ยอดขายเงินสดเป็นยอดสุทธิหลังทอน ไม่ใช่จำนวนเงินที่รับก่อนทอน และไม่รวมเงินสดตั้งต้นในรายได้

พิมพ์ซ้ำได้จากเมนู **สรุปกะ → เลือกกะ → พิมพ์สรุปปิดกะ** รองรับกะที่ข้ามเที่ยงคืนโดยยึด shiftId ไม่ใช่วันที่ชำระ การพิมพ์ไม่เปิดลิ้นชักหรือปิดกะซ้ำ หากเครื่องพิมพ์หลุด กะยังปิดสำเร็จแล้ว ให้เลือกกะเดิมเพื่อพิมพ์ซ้ำ ไม่มี migration ใหม่ แต่ต้องอัปเดต backend พร้อม desktop รุ่นนี้ การเปิดผ่านเบราว์เซอร์จะแสดงใบสรุปและให้กดพิมพ์ผ่านไดรเวอร์ Windows

1. พนักงานเข้าสู่ POS แล้วกด **เปิดร้าน** กรอกเงินสดตั้งต้นในลิ้นชัก ระบบเปิดได้ครั้งละหนึ่งรอบต่อร้าน ใช้ร่วมกันทุกเครื่องและทุกพนักงาน
2. คิดเงินตามปกติ บิลใหม่ต้องผูกกับรอบเปิดร้านที่ยังไม่ปิด บิลที่ปิดไปแล้ว retry หลังร้านปิดได้โดยไม่สร้างยอดซ้ำ
3. กด **ปิดร้าน / นับเงินสด** แล้วกรอกยอดที่นับจริง รวมเงินตั้งต้น ระบบบันทึกผู้เปิด/ผู้ปิด เวลา ยอดเงินที่ควรมี และส่วนต่างขาด/เกิน เงินที่ควรมี = เงินตั้งต้น + ยอดขายเงินสดสุทธิหลังทอน ไม่รวมยอดโอน
4. **สรุปรายวัน** เลือกวันที่ได้ ยอดรวม/จำนวนบิล/เงินสด/โอนนับตามเวลาชำระจริง 00:00 ถึงก่อนเที่ยงคืนถัดไปใน `Asia/Bangkok` ส่วนสรุปปิดร้านเป็นยอดของรอบเปิดนั้น จึงอาจต่างจากรายวันเมื่อเปิดร้านข้ามเที่ยงคืน

เปิด/ปิดร้านและบิลตรวจพร้อมกันด้วย transaction แบบ Serializable บิลใหม่กับการปิดร้านแก้แถวรอบเดียวกันเพื่อป้องกันบิลหลุดสรุป เมื่อได้ 409 ให้โหลดสถานะแล้ว retry รายการเดิม คำขอเปิดร้านมี key และปิดร้านอ้างอิง shiftId เพื่อป้องกันการส่งซ้ำ

## โปรแกรม Windows และ .exe

ทดสอบ desktop จากโฟลเดอร์ `pos` ด้วย `npm.cmd run dev` (หรือ `npm.cmd start`) โดยเปิด backend ด้วย `npm.cmd run dev:api` จาก root ในอีก Terminal ก่อน ค่าเริ่มต้นเชื่อม `http://localhost:3001/pos/`

รัน `npm.cmd install --prefix pos` แล้ว `npm.cmd run build:pos` จาก root จะได้ตัวติดตั้งใน `pos/release/` ค่าเริ่มต้นเป็น Windows x64; ถ้าแท็บเล็ตเป็น ARM ต้อง build และทดสอบ ARM64 แยกกัน Android ใช้ .exe ไม่ได้

แอปสร้าง `%APPDATA%/8sian-pos/server.json` ในการเปิดครั้งแรก ตั้งค่า `url` เป็น `https://โดเมน-backend/pos/` แล้วเปิดแอปใหม่ อนุญาต HTTP เฉพาะ localhost สำหรับพัฒนา ต้อง deploy `pos/web` พร้อม backend (อย่าคัดลอกเฉพาะ backend)

โปรแกรมเป็น client ออนไลน์ ไม่ได้ติดตั้งฐานข้อมูล/backend ลงแท็บเล็ต ตัวติดตั้งยังไม่มีใบรับรอง code signing ของร้าน

## รับเงินและบิลค้าง

หน้าคิดเงินบนแท็บเล็ตใช้พื้นที่เต็มความสูงจอ ยอดรวมและปุ่มยืนยันอยู่ในตำแหน่งเดิม รายการสินค้าและตะกร้าเลื่อนภายในแยกกัน ช่องสมาชิกและคูปองอยู่ด้านล่างรายการสินค้า เลือกวิธีชำระผ่านปุ่ม **เงินสด / โอนเงิน** โดยโอนเงินซ่อนช่องรับเงินสดและใช้ยอดชำระตรงกับยอดบิล

เลขใบเสร็จใช้ `YYMMDDHHmm` ตามเวลาไทยและปี ค.ศ. ต่อด้วยลำดับบิลประจำวันอย่างน้อย 3 หลัก เช่น `2610291006001` ลำดับเริ่ม `001` ใหม่เมื่อเปลี่ยนวัน และเพิ่มต่อเนื่องแม้เวลาเปลี่ยนนาที เมื่อเกิน 999 ใช้ 1000 ต่อได้ ระบบออกเลขพร้อมบันทึกบิลใน transaction เดียว retry และพิมพ์ซ้ำใช้เลขเดิม Migration `202610290003_pos_receipt_numbers` เติมเลขให้บิลเดิมจากเวลาชำระและลำดับของวันนั้นด้วย

เงินสดคำนวณทอนเป็นสตางค์ โอนเงินต้องให้พนักงานตรวจยอดเงินจริงด้วยตนเอง ยังไม่มี payment gateway หรือ QR ชำระเงินอัตโนมัติ ราคาและยอดรวมตรวจจากฐานข้อมูลอีกครั้งก่อนบันทึก

บิลที่ส่งแล้วจะเก็บ idempotency key และ payload ชั่วคราวใน localStorage ของ POS รวมถึง QR สมาชิกถ้าผูกบิล จนได้ผลยืนยัน ห้ามล้างข้อมูลแอป/เปิด POS หลายหน้าต่าง/รับเงินซ้ำระหว่างมีบิลค้าง หากปิดโปรแกรมหลังส่ง ให้เปิดใหม่แล้วกดตรวจผลบิลเดิม บิลที่ตอบ 400 ยังไม่ถูกบันทึกและต้องแก้ข้อมูล ส่วน network failure/409 เก็บ key เดิมเพื่อ retry

บิล สะสมครั้ง และ audit บันทึกใน transaction เดียว มีบัญชีแคชเชียร์ USER และรอบเปิด–ปิดร้านแล้ว ยังไม่มี offline checkout, stock, คืนเงิน, ภาษี, เงินเข้า/ออกลิ้นชักนอกการขาย หรือรอบกะแยกต่อพนักงาน

ตรวจสอบด้วย `npm.cmd test` และ `npm.cmd run test:pos -w backend` (integration ใช้ schema ชั่วคราวใน PostgreSQL localhost แล้วลบทิ้ง ไม่แก้ข้อมูลร้าน)

## เครื่องพิมพ์ Worrex และลิ้นชักเดิม

ใบเสร็จใช้โลโก้ที่คัดลอกจาก `frontend/public/images/logo.png` ไปไว้ใน `pos/web/images/logo.png` แสดงชื่อร้านและที่อยู่สาขาติวานนท์ ตามด้วย displayName ของผู้ที่ออกบิล เลขบิล ตารางรายการ ยอดรวม และการชำระ ข้อความขอบคุณและเวลาชำระตามเวลาไทยอยู่ท้ายใบเสร็จ การพิมพ์ซ้ำค้นชื่อจากเจ้าของบิลเดิม ไม่ใช้ชื่อคนที่กดพิมพ์ซ้ำ บิลเก่าที่ไม่มีบัญชีพนักงานจะแสดงว่าไม่ระบุ

เมื่อผูกสมาชิกกับบิล ระบบแสดงเบอร์สมาชิกเต็มในรูปแบบ `081-234-5678` ใต้ชื่อสมาชิกใน POS และใต้เลขที่บิลบนใบเสร็จ ทั้งการค้นหาด้วยเบอร์และการสแกน QR สมาชิก การพิมพ์ซ้ำดึงเบอร์จากสมาชิกที่ผูกกับบิลนั้น บิลลูกค้าทั่วไปไม่แสดงบรรทัดเบอร์สมาชิก

โปรแกรม Windows รุ่น 0.2.0 มีเมนู **อุปกรณ์** สำหรับเชื่อม WORREX JP80H ผ่าน Bluetooth LE โดยตรง ไม่ต้องมี printer queue ของ Windows ดูขั้นตอนใน [HARDWARE.md](HARDWARE.md) พิมพ์ภาษาไทยและโลโก้เป็นภาพ 576 จุด (72 มม.) สำหรับกระดาษที่วัดได้ 78 มม. / ม้วนกลุ่ม 80 มม. มี CODE128 เลขใบเสร็จ และปุ่มพิมพ์บาร์โค้ดสินค้าจากข้อมูลสินค้าในระบบ กระดาษ 58 มม. ไม่รองรับโปรไฟล์นี้

พิมพ์อัตโนมัติหลัง backend บันทึกบิลเท่านั้น การส่งซ้ำของบิลเดิมใช้ claim บนเซิร์ฟเวอร์ป้องกันคำสั่งอัตโนมัติซ้ำข้ามเครื่อง พิมพ์ซ้ำจาก **บิลล่าสุด** ไม่รับเงิน/ตัดคูปอง/สะสมครั้งซ้ำ และไม่เปิดลิ้นชัก ถ้าการส่งขาดกลางทางให้ตรวจกระดาษแล้วพิมพ์ซ้ำเองจากบิลเดิม ไม่มีการส่งคำสั่งอัตโนมัติซ้ำหลัง timeout

ลิ้นชัก WORREX ต่อผ่านเครื่องพิมพ์ ใช้คำสั่ง ESC/POS ที่ทดสอบแล้ว `1B 40 1B 70 30 64 FA` (ขา 2, ON 200 ms / OFF 500 ms) เปิดอัตโนมัติเฉพาะเงินสดเมื่อเปิดตัวเลือกไว้ การเปิดด้วยตนเองต้องกรอกเหตุผลและเข้าสู่ POS มี audit ผู้สั่งและผลการส่ง คำตอบ SENT หมายถึงเครื่องพิมพ์รับข้อมูล ไม่ใช่เซ็นเซอร์ยืนยันว่าลิ้นชักเปิด รุ่นใหม่เริ่มต้นปิด auto-drawer ให้ทดสอบสายและล็อกก่อนเปิดใช้

เครื่องสแกน USB/Bluetooth ใช้ HID keyboard พร้อม Enter suffix ในช่องสินค้า/สมาชิกหรือช่องคูปองเดิม การพิมพ์บาร์โค้ดลงกระดาษใบเสร็จไม่ใช่การพิมพ์สติกเกอร์แบบมี gap sensor หากเปิด POS ใน Chrome/Edge จะยังใช้ `window.print()` ผ่านไดรเวอร์ Windows; การเชื่อม BLE และลิ้นชักในรุ่นนี้ต้องใช้โปรแกรม Windows
