# ระบบดูแลหลังบ้านบนเว็บ

เปิดเส้นทางแอดมินเดิมของร้าน แล้วเข้าสู่บัญชี ADMIN เดิม สิทธิ์ตรวจที่ API ทุกครั้ง บัญชีสมาชิกและพนักงาน POS ไม่มีสิทธิ์จัดการข้อมูลหลังบ้าน

## เมนูที่ใช้งานได้

- **สมาชิก**: ค้นด้วยชื่อ เบอร์ หรือเลขสมาชิก เพิ่มบัญชีเมื่อสมาชิกยอมรับนโยบายแล้ว แก้ชื่อ/เบอร์/วันเกิด แจกคูปอง ตั้งรหัสผ่านสมาชิก และยกเลิกคูปองที่ยังไม่ใช้พร้อมเหตุผล
- **แคมเปญคูปอง**: สร้าง ค้นหา แก้เงื่อนไขก่อนแจก เปิด–ปิดแจก และลบรายการที่ยังไม่มีคูปองหรือแคมเปญถัดไปอ้างอิง การเปลี่ยนเงื่อนไขตรวจไม่ให้เกิดวงจร
- **สะสมครั้ง**: ค้นสมาชิก/สแกน QR และบันทึกครั้งตามใบเสร็จผ่านระบบเดิม
- **พนักงานและสินค้า POS**: เพิ่ม/แก้ชื่อพนักงาน ระงับหรือเปิดบัญชี ตั้งรหัสผ่านใหม่โดยยืนยันรหัสแอดมิน ค้นหา/เพิ่ม/แก้สินค้าและราคา เปิด–หยุดขาย ลบรายการที่ยังไม่ใช้ และตั้งยอดขั้นต่ำคูปอง
- **ยอดขายและกะ**: เลือกช่วงวันที่ได้ไม่เกิน 93 วัน ดูยอดขายสุทธิ เงินสด เงินโอน จำนวนบิล ค้นเลขบิล/กรองวิธีชำระ ดูรายละเอียดสินค้าในบิล และดูสรุปกะพร้อมยอดตรวจนับเงินสด ส่งออก CSV เฉพาะหน้าที่แสดงได้
- **ประวัติระบบ**: ดูผู้ดำเนินการ เวลา รายการและเหตุผล รวมการเพิ่ม แก้ไข ลบ ยกเลิกคูปอง และการจัดการ POS

## การลบและประวัติ

ทุกการลบต้องพิมพ์ชื่อรายการให้ตรงและกรอกเหตุผลอย่างน้อย 5 ตัวอักษร API ตรวจความสัมพันธ์อีกครั้งใน transaction และบันทึก audit พร้อมกัน

- สมาชิกที่มีคูปอง ครั้งสะสม หรือยอดขายแล้วลบไม่ได้
- สินค้าที่เคยอยู่ในบิลแล้วให้ใช้ **หยุดขาย** เพื่อคงประวัติเดิม
- พนักงานที่เคยรับเงิน เปิด/ปิดกะ หรือมีการจองคูปองอยู่ให้ใช้ **ระงับบัญชี**
- แคมเปญที่แจกคูปองแล้วไม่แก้เงื่อนไขย้อนหลัง ให้ปิดแจกและสร้างแคมเปญใหม่
- คูปองที่ชำระแล้วหรือกำลังอยู่ในบิล POS ที่ยังจองสิทธิ์อยู่ยกเลิกไม่ได้ การยกเลิกคูปองที่ยังไม่ใช้จะทำให้สิทธิ์หมดอายุและล้างบาร์โค้ด โดยคงประวัติแจกไว้
- บิลชำระเงินและกะที่ปิดแล้วเป็นข้อมูลอ้างอิง ไม่เปิดปุ่มลบทิ้งในระบบนี้

แก้เบอร์สมาชิกแล้วระบบยกเลิกเซสชันและ QR เก่า ให้สมาชิกเข้าสู่ระบบใหม่ ตั้งรหัสผ่านพนักงาน/ระงับพนักงานจะยกเลิกเซสชัน POS ของบัญชีนั้น รหัสผ่านไม่ถูกส่งกลับใน API หรือ audit

ยอดขายนับตามเวลาชำระ 00:00–24:00 ของ Asia/Bangkok ส่วนรายการกะกรองตามวันที่เปิดกะ ใบสรุปกะยึด shiftId จึงครอบคลุมกะที่ข้ามเที่ยงคืนได้ รายได้ไม่รวมเงินสดตั้งต้นในลิ้นชัก

## ตรวจสอบและใช้งานในเครื่อง

รัน backend และ frontend เดิม ไม่ต้องมี migration ใหม่สำหรับชุดนี้ ต้อง deploy ทั้งสองส่วนพร้อมกันเมื่อจะนำขึ้นเซิร์ฟเวอร์จริง

- `npm.cmd run build -w frontend`
- `npm.cmd run check:views -w frontend`
- `npm.cmd test -w backend`
- จาก backend: `node --env-file=.env scripts/check-admin-management.mjs` (สร้าง schema ชั่วคราวเฉพาะ PostgreSQL localhost แล้วลบทิ้ง ไม่แก้ข้อมูลร้าน)
- จาก root: `.\pos\node_modules\.bin\electron.cmd frontend/scripts/check-admin-management.cjs` (ทดสอบเว็บ build ด้วย API จำลอง ไม่มีการแก้ข้อมูลร้าน)
