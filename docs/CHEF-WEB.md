# หน้าครัวบนเว็บ

เปิด `/chef` บนโดเมน frontend แล้วเข้าสู่ระบบด้วยบัญชี POS บทบาท `CHEF` (บัญชีพนักงาน `USER` ใช้ได้เช่นกัน) บัญชีนี้เป็นคนละระบบกับบัญชีสมาชิกและแอดมิน

- แสดงออเดอร์รอทำเรียงเก่าไปใหม่ อัปเดตทุก 5 วินาที
- กดสำเร็จแล้วเพื่อนำออเดอร์ออกจากคิว
- ยกเลิกรายการอาหารหรือทั้งใบ โดยยืนยันก่อนยกเลิก
- เลือกโต๊ะที่ยังมีลูกค้าเพื่อดูยอดอาหารสำเร็จของรอบปัจจุบัน
- เปิดใบอาหารแล้วกดพิมพ์ผ่านหน้าต่างพิมพ์ของเบราว์เซอร์

ใช้ `/api/pos` และ cookie session เดียวกับ POS ไม่ต้องเพิ่ม migration หรือสร้างบัญชีแบบใหม่ การเปลี่ยนสถานะออเดอร์มีผลกับ POS ทันทีที่โหลดข้อมูลใหม่

ตั้งค่าเว็บเซิร์ฟเวอร์ให้เส้นทาง `/chef` ส่งกลับ frontend `index.html` เช่นเดียวกับเส้นทางหน้าเว็บอื่น และให้ frontend เข้าถึง backend เดิมได้

## เชื่อมต่อเครื่องพิมพ์

### ES-9910UB บน Windows

รุ่นนี้เป็นเครื่องพิมพ์ฉลาก ให้ใช้โหมดหน้าต่างพิมพ์ของระบบผ่านไดรเวอร์ ES-9910UB โดยตั้งพอร์ต Bluetooth COM3 ตามอุปกรณ์ที่ตรวจพบ (พอร์ตอาจต่างกันในเครื่องอื่น) ยังไม่ได้ยืนยันว่ารองรับคำสั่ง ESC/POS โดยตรง ความกว้างหน้าพิมพ์เว็บตั้งไว้ 80 มม. ตามใบเสร็จ POS เดิม เลือกกระดาษและความสูงในไดรเวอร์ให้ตรงของจริง กดพิมพ์ทดสอบผ่าน Windows แล้วเลือกเครื่องและมาตราส่วน 100% ผลจากหน้าต่างพิมพ์ไม่ได้ยืนยันว่ามีกระดาษออกจริง

กด **เครื่องพิมพ์** บนแถบเครื่องมือแล้วเลือกวิธีพิมพ์:

- **หน้าต่างพิมพ์ของระบบ**: ใช้เครื่องพิมพ์ที่ติดตั้งในระบบปฏิบัติการ
- **Serial / COM (ESC/POS)**: ใช้ HTTPS บนเบราว์เซอร์คอมพิวเตอร์ที่รองรับ Web Serial เลือกความเร็วตามคู่มือเครื่อง ขนาดกระดาษ 58/80 มม. แล้วกดเลือกและเชื่อมต่อ เครื่อง USB ต้องมีพอร์ต COM และ Bluetooth ต้องจับคู่ในระบบให้มีพอร์ต Serial ก่อน โหมดนี้ไม่รองรับ USB/BLE ทุกรุ่นโดยตรง
- **อุปกรณ์ Bluetooth ของ POS**: แสดงเมื่อมี `window.posHardware` จากแอป POS สามารถค้นหา เชื่อมต่อ บันทึกการตัดกระดาษ และพิมพ์ทดสอบได้

เมื่อเลือกพิมพ์โดยตรง ปุ่มพิมพ์ในใบอาหารจะส่งไปยังอุปกรณ์ที่เลือก พิมพ์ Serial เป็นภาพเพื่อรองรับภาษาไทย และบันทึกเหตุการณ์ผ่าน API เดิม ต้องเชื่อมต่อใหม่หลังโหลดหน้าใหม่ ตรวจใบอาหารจริงก่อนพิมพ์ซ้ำหากการส่งข้อมูลล้มเหลว
