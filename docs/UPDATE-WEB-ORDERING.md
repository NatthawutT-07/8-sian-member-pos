# อัปเดตหน้าโต๊ะและเมนูสั่งอาหาร

การเปลี่ยนแปลงนี้อยู่ในทั้ง `frontend` และ `backend` ซึ่งเป็น Git repository แยกกัน ต้องนำขึ้นระบบทั้งสองส่วน

## การใช้งาน

- หน้าแอดมินเลือกโต๊ะจาก dropdown และดาวน์โหลด QR ทีละโต๊ะ ส่วนเพิ่มช่วงหมายเลขโต๊ะอยู่ในหัวข้อพับเก็บ
- ตั้งลำดับแต่ละหมวดหมู่แล้วกด “บันทึกลำดับหมวดหมู่” ลำดับที่ 1 แสดงก่อน ใช้ร่วมกันทุกโต๊ะ แต่แสดงเฉพาะหมวดหมู่ที่มีอาหารเปิดให้สั่งในโซนที่โต๊ะได้รับสิทธิ์
- ส่วน “ลำดับอาหารภายในหมวดหมู่” ใช้กำหนดลำดับชื่ออาหาร เลือกหมวดหมู่ เปลี่ยนหมายเลขลำดับ แล้วกด “บันทึกลำดับอาหาร” รายการอื่นจะเลื่อนตามอัตโนมัติ ตัวเลขแสดงเฉพาะหลังบ้าน หน้าลูกค้าคงรูปแบบเดิมและรับรายการที่เรียงแล้วโดยไม่มีข้อมูลเลขลำดับ
- ลำดับอาหารใช้ร่วมกันในหมวดหมู่เดียวกันทุกโซน รวมรายการที่ปิดให้สั่ง เพื่อคงตำแหน่งเมื่อเปิดขายอีกครั้ง ลูกค้าเห็นเฉพาะเมนูที่เปิดและมีสิทธิ์ เมนูเพิ่มใหม่จะอยู่หลังรายการที่เคยจัดลำดับไว้ จัดลำดับใหม่ได้ตามต้องการ
- เพิ่มเมนูโดยเลือกโซนและหมวดหมู่เดิม หรือเลือกเพิ่มชื่อใหม่ จากนั้นกรอกชื่ออาหารและรูป เมื่อบันทึกแล้วจะเก็บโซนและหมวดหมู่ไว้สำหรับรายการถัดไป
- รายการเมนูแบ่งตามหมวดหมู่ ค้นหาชื่อและกรองโซน/หมวดหมู่ได้ กดแก้ไขเพื่อเปิดเมนูในฟอร์มด้านบน
- หน้าสั่งอาหารบนมือถือใช้ dropdown หมวดหมู่ ส่วนจอใหญ่ใช้ปุ่มหมวดหมู่ตามลำดับเดียวกัน
- หน้า “จัดการ POS” มีส่วน “จัดลำดับสินค้าในแต่ละกลุ่ม” ใต้ฟอร์มสินค้า เลือกกลุ่มหลัก/ส่วนลด/โปรโมชั่น เปลี่ยนลำดับ แล้วกด “บันทึกลำดับสินค้า” จากนั้นให้ POS โหลดรายการใหม่ ลำดับนี้รวมสินค้าที่หยุดขายเพื่อคงตำแหน่งเมื่อเปิดขายอีกครั้ง และไม่เปลี่ยนราคาหรือการคิดเงิน

## ขั้นตอนนำขึ้นระบบ

1. บน server สำรองฐานข้อมูลตามขั้นตอนเดิม จากนั้นอัปเดต backend (ตัวอย่างนี้ใช้โฟลเดอร์ `~/8-sian-member-backend` และ PM2 process `8sian-backend` ตามคู่มือระบบเดิม):

   ```sh
   cd ~/8-sian-member-backend
   git status --short
   git pull --ff-only origin main
   pm2 stop 8sian-backend
   npm ci && npm run generate && npm run migrate && pm2 restart 8sian-backend --update-env
   ```

   Migration `202611090001_ordering_category_order` เพิ่มตาราง `OrderingCategory` เพื่อเก็บลำดับหมวดหมู่ เมนูและ QR โต๊ะเดิมใช้ต่อได้ หมวดหมู่ที่ยังไม่กำหนดลำดับอยู่หลังหมวดหมู่ที่บันทึกลำดับแล้ว

   Migration `202611100001_ordering_item_order` เพิ่ม `OrderingMenuItem.sortOrder` เพื่อเก็บลำดับรายการภายในหมวดหมู่ ต้องรัน migration และ generate Prisma Client ก่อนเริ่ม backend รุ่นใหม่นี้

   Migration `202611100002_pos_product_order` เพิ่ม `PosProduct.sortOrder` เพื่อเก็บลำดับสินค้าภายในกลุ่ม POS แอป POS เดิมรับลำดับจาก backend ได้โดยโหลดรายการใหม่ ไม่ต้องสร้างตัวติดตั้งใหม่เฉพาะการปรับลำดับสินค้านี้

   Migration `202611100003_ordering_throttle` เพิ่มตัวนับป้องกันการส่งออเดอร์ถี่ รายละเอียดการลดโหลดเมนูและผลทดสอบ 100 คนอยู่ใน [ORDERING-CAPACITY.md](ORDERING-CAPACITY.md)

   ถ้า `git status --short` แสดงไฟล์ที่แก้ค้าง ให้ตรวจสอบก่อน pull หากขั้นตอนใดผิดพลาดให้หยุดและแก้ก่อนดำเนินการต่อ คงค่า `.env` เดิมไว้ และไม่ใช้ `prisma migrate reset`

2. ตรวจผลหลังรีสตาร์ต:

   ```sh
   pm2 status
   pm2 logs 8sian-backend --lines 50 --nostream
   curl --fail-with-body https://api.8sianracha.com/api/health
   pm2 save
   ```

   Health ต้องตอบ `{"status":"ok"}`
3. อัปเดต frontend และ build โดยใช้ค่า `VITE_API_URL` เดิม แล้วนำ `frontend/dist` ขึ้นระบบตามขั้นตอนเดิม

## ผลตรวจในเครื่องพัฒนา

- Backend tests ผ่าน 94 รายการ รวมลำดับหมวดหมู่/รายการอาหาร/สินค้า POS แคชเมนู การป้องกันออเดอร์ซ้ำและส่งถี่ และการกรองตามสิทธิ์โต๊ะ
- Frontend production build และ check:views ผ่าน
- ทดสอบ UI ด้วยข้อมูลจำลองผ่าน: เลือกโต๊ะ จัดลำดับและบันทึกหมวดหมู่ แก้ไข/เพิ่มเมนู เพิ่มหมวดหมู่ใหม่ เก็บกลุ่มเดิมสำหรับรายการถัดไป กรองเมนู และหน้าเว็บมือถือไม่มีการล้นแนวนอน

รัน migration และ generate Prisma Client ในเครื่องพัฒนาแล้ว ยังไม่ได้ deploy หรือรัน migration บนระบบจริง
